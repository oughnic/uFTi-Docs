# Decision log

What has been decided, what is proposed, and what still needs an answer.

Part of the [authoring plan](authoring-plan.md). Status: Draft 0.4, 16 October 2026.

**How to use this log.** A decision is *Proposed* until the maintainer accepts it in a pull request, which changes its status to *Accepted* and records the date. Questions stay open until answered, and the answer becomes a decision. When a decision changes, edit its row and note why. Do not delete history.

| DEC-046 | **Tool pinning and folders.** `build/tools.lock` pins every tool by version, address, size and SHA-256, with per-platform entries (x64 and arm64) and an x64 fallback for Windows on ARM. Bootstrap installs into `.tools/` at the root on Linux and macOS and into `%LOCALAPPDATA%\ufti-tools` on Windows (`UFTI_TOOLS` overrides). Where upstream publishes no checksum (DITA-OT, the readability rules) the lock records the checksum of the file verified by hand; veraPDF's is the one the plugin project's CI pins for the same signed build; the Nu HTML Checker is pinned as the `vnu-jar` npm package, because GitHub carries only a rolling release. | Proposed (WP1, 17 October 2026) | A toolkit path of 111 characters (a worktree under the repository) overran `dita.bat`'s command line, exactly as DEC-015 feared. | DEC-047 | **Search and the PDF are required in every build** (`govuk.search=yes`, `govuk.pdf=yes`), locally as in CI. | DEC-048 | **Prose and the reading level are measured by Vale on the DITA source.** Vale converts each topic with the toolkit's stock html5 transformation (the toolkit's `bin` on the PATH) and measures it: Flesch reading ease 70 or more and Flesch-Kincaid grade 6 or lower per topic, an average sentence of 15 words or fewer, no sentence over 25, British spelling with SCOWL's `en_GB-ise` dictionary, and the words the standards rule out (DEC-029, DEC-030, DEC-040). The readability rules and the dictionary are vendored under `build/vale/` with their licences, so CI never syncs packages. WP3 grows the project style. | Proposed (WP1, 17 October 2026) | Measures the words an author writes, in the file they wrote them in. Vale's own DITA support does the conversion, and it runs on Windows through `dita.bat`. | WP3's style guide; the thresholds move if DEC-029's measures prove too blunt. |
| DEC-049 | **The checks are PowerShell on every operating system;** bash twins exist only for bootstrap and build. The plugin repository's Python and Node checkers (links, metadata, page weight, axe-core) run in CI, and locally through the pinned containers in `tools.lock` when Docker is present. | Proposed (WP1, 17 October 2026) | One implementation per gate. PowerShell 7 is on every GitHub runner and on the authoring machine. | n/a |
| DEC-050 | **Unresolved keys are gated by the source lint,** which resolves every key per manual through its DITAVAL filter and fails on one that is undefined, an image key whose file is missing or whose key has no link text, and an orphan topic, picture or diagram. | Proposed (WP1, 17 October 2026) | DITA-OT 4.4.1 says nothing about an unresolved key: the element is written empty (`<span class="uicontrol"></span>`, `<img>` with no source or alt), and no message of any level appears. A missing image file does report `DOTX008E`, which the build gates. | The toolkit reports unresolved keys. |
| DEC-051 | **Diagram conventions** (amends DEC-036): a `title` and a `desc`, `role="img"`, and **no `aria-labelledby` or `aria-describedby`**; links written relative to the page that shows the diagram, as `.html` addresses. The lint enforces all of it. | Proposed (WP1, 17 October 2026) | The plugin prefixes every id when it inlines a diagram and leaves those two attributes as written, so they pointed at nothing; the `title` names the diagram without them, and the plugin adds `aria-label` from the figure title when there is no `title`. Links inside the file are inlined unchanged, so they resolve from the page. Worth a fix in the plugin: rewrite `aria-labelledby` and `aria-describedby` with the ids. | The plugin rewrites the idrefs. |
| DEC-052 | **CI shape.** `lint`; `build` per manual, twice, compared byte for byte; `check` per output; the stock-html5 `smoke` build (DEC-042); a `build on Windows` job through `dita.bat`; and `ci`, the one check branch protection requires. Weekly on a schedule against the pinned tools. `deploy` (`main` only) and `release` (`v*` tags) wait for `build/projects/site.xml`, which WP7 adds; the fixture is never published. GitHub Pages must be enabled with Actions as its source before the first deploy. | Proposed (WP1, 17 October 2026) | Build and quality, section 5, made concrete. | WP7. |
| DEC-053 | **Every deliverable's output folder is cleared before a build, and the determinism gate compares everything but the search index.** | Proposed (WP1, 17 October 2026) | The toolkit writes into the folder without clearing it and Pagefind leaves old index fragments behind, so a second build into a used folder was not byte-identical. Into clean folders, two builds are the same, PDF included, except Pagefind's index files, whose bytes differ between runs on identical pages; the plugin's own determinism check builds without search for the same reason. | Pagefind writes a stable index. |
| DEC-054 | **Accessibility exceptions are documented, dated and few.** The axe-core gate (`build/scripts/a11y.mjs`) fails on every WCAG 2.2 AA violation except those listed in `build/scripts/a11y-exceptions.json`, where each entry names the rule, the elements it covers, the reason and the date it was added. The first entry: plugin 1.3.0 gives every inlined diagram `role="img"`, so a clickable diagram's links count as interactive content nested in an image (`nested-interactive`); readers using assistive technology reach the same links in the list that follows every diagram (DEC-036). The entry goes when the plugin gives a diagram with links another role. A second axe finding, related links set too close to touch (`target-size`), is fixed in the theme rather than excepted. | Proposed (WP1, 17 October 2026) | A gate with silent exclusions is no gate; one with a dated list is. Both findings are the plugin's to fix, and the maintainer can. | The plugin changes. |
| DEC-055 | **Branch protection and repository settings.** Rulesets `dev` and `main`, with no bypass (administrators included): a pull request is required, with no approval count while there is one maintainer, stale reviews dismissed on a new push and every conversation resolved; the `ci` check of the CI workflow must pass on a branch that is up to date; deletions and force pushes are blocked. GitHub Pages is enabled with GitHub Actions as its source at `https://oughnic.github.io/uFTi-Docs/` (nothing is deployed until `build/projects/site.xml` exists, WP7). Private vulnerability reporting is on, so the form `SECURITY.md` points at exists. | **Accepted** (maintainer instruction, 17 October 2026) | DEC-016 and build and quality, section 7. Raise the approval count when a second reviewer exists. | A second maintainer joins; hosting moves (Q26). |
